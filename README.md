# Ashara

Autonomous development system. Describe a vision, get working software.

Ashara handles decomposition, planning, coding, verification, and delivery — without human intervention between steps. It operates as a contractor: you provide direction, it makes every implementation decision on its own, schedules its own work, and self-corrects when things go wrong.

> **Pre-alpha.** Under active development.

## Why

Current AI coding tools are sophisticated autocomplete. They assist — they don't ship. The gap between "AI wrote this function" and "AI built this project from a sentence" is orchestration: who decides what to build next, how to verify it, and what to do when it breaks.

Ashara closes that gap. It is not a copilot, not a framework, not a library. It is a system that owns the entire lifecycle from vision to running software.

## Design Principles

**Client-contractor, not tool-user.** The interaction model is a client hiring a contractor. The contractor doesn't stop working because the client hasn't replied. Direction changes are expected and handled without halting — the system adjusts immediately, and if the client reverses course, it adjusts again. The contractor can communicate impact and cost, but cannot refuse the client's decisions.

**Vision in, software out.** The system focuses on building new projects from scratch (0-to-1). In a greenfield scenario, all context is generated by the system itself — no reverse-engineering of existing tacit knowledge required.

**Deterministic where possible, LLM only where necessary.** Scheduling, dependency resolution, convention enforcement, and lifecycle management are deterministic code. LLMs handle what requires semantic judgment: planning, brief assembly, goal alignment checks. If a linter can enforce it, a prompt shouldn't.

**Better retrieval beats bigger models.** Investing in what context an agent receives yields higher ROI than investing in a smarter model. A focused brief assembled from structural, semantic, lexical, and knowledge retrieval outperforms dumping the entire codebase into a large context window. Irrelevant context is not neutral — it actively degrades performance.

**Safety is structural, not aspirational.** Agents execute in sandboxed containers with no permissions by default — capabilities are explicitly granted, not implicitly available. Convention compliance is enforced by linters, not prompts. Budget enforcement is policy with hard ceilings, not alerts that someone might read.

**Agents have attention limits too.** An LLM agent's context window is its working memory, and it is stricter than a human's — exceed it and information is truly invisible. Many practices designed to manage human cognitive load (controlling communication scope, limiting task breadth, structured handoffs) apply equally to agents. The quality of a dispatch brief directly determines execution quality.

**Share state, don't synchronize context.** Rather than trying to give every agent the same context, let them query a shared knowledge store as the single source of truth. Context synchronization is expensive, lossy, and fragile. State sharing is cheap, consistent, and auditable.

**Capture knowledge at the moment of decision.** Tacit knowledge — why something was chosen, what alternatives were rejected, what constraints applied — cannot be extracted after the fact. The system records decisions as they happen, not in retrospective summaries. Raw findings are preserved as-is; extracted summaries serve as retrieval indexes, not replacements.

**Progressive decomposition.** Work is broken down incrementally: decide the big picture first, defer details until they are needed. Later phases reference the completed results of earlier phases, producing more precise plans than upfront decomposition ever could.

**Convention over configuration, enforcement over trust.** Coding standards are defined once and enforced deterministically on every cycle. The system does not trust that an agent "remembered" a convention — it verifies. Smarter models are better at finding constraint loopholes, not better at following constraints.
